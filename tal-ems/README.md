# TAL EMS — نظام الإدارة المتكامل لشركة تال الإنشائية للمقاولات

نظام إداري وتشغيلي متكامل (Enterprise Management System) يعمل كمقر إداري إلكتروني للشركة: المشاريع، الموظفون، الحضور، المهام، المالية، المشتريات، المستودعات، التقارير، المستندات، الاجتماعات والقرارات، المراسلات، الإشعارات، وسجل العمليات — بصلاحيات حقيقية مخزنة في قاعدة البيانات.

---

## 1. التقنيات

| الطبقة | التقنية |
|---|---|
| الواجهة | React 19 + Vite، أيقونات Lucide، رسوم Recharts، خط IBM Plex Sans Arabic (مضمّن محلياً) |
| الخادم | Node.js 22 + Express |
| قاعدة البيانات | PostgreSQL 16 عبر Knex (Migrations) |
| الأمان | bcrypt، JWT في Cookie من نوع httpOnly + SameSite=Strict مرتبط بجلسة في قاعدة البيانات، TOTP للمصادقة الثنائية، Helmet/CSP، تحديد معدل محاولات الدخول |
| التصدير | Excel (ExcelJS مع الشعار)، PDF عبر محرك الطباعة في المتصفح (لضمان تشكيل الحروف العربية بشكل صحيح) |

## 2. التشغيل المحلي (للتجربة)

المتطلبات: Node.js 20 أو أحدث، وPostgreSQL 14 أو أحدث.

```bash
# 1) قاعدة البيانات
createdb tal_ems            # أو عبر psql: CREATE DATABASE tal_ems;

# 2) الإعداد
cp server/.env.example server/.env      # عدّل DATABASE_URL وJWT_SECRET وOWNER_PASSWORD
npm run install:all
npm run setup               # إنشاء الجداول + الصلاحيات + المناصب + حساب المالك
npm run demo:seed           # (اختياري) تحميل بيانات تجريبية

# 3) التشغيل أثناء التطوير
npm run dev:server          # API على المنفذ 4000
npm run dev:client          # الواجهة على http://localhost:5173

# أو تشغيل إنتاجي من خادم واحد:
npm run build && npm start  # http://localhost:4000
```

### حسابات التجربة (بعد `demo:seed`) — كلمة المرور لجميعها: `TalDemo2026`

| اسم المستخدم | المنصب | ماذا يرى |
|---|---|---|
| `demo.owner` | مالك الشركة | كل شيء، بما فيه سجل العمليات والإعدادات والنسخ الاحتياطي |
| `demo.ceo` | المدير التنفيذي | جميع الإدارات واعتماد القرارات التشغيلية (القرارات الاستراتيجية للمالك فقط) |
| `demo.cfo` | المدير المالي | المالية والاعتماد المالي والرواتب |
| `demo.hr` | مدير الموارد البشرية | الموظفون، الحضور، الإجازات، التقييمات |
| `demo.pm` / `demo.pm2` / `demo.pm3` | مدير مشروع | مشاريعه فقط وفريقها وميزانيتها |
| `demo.procurement` | مسؤول المشتريات | المشتريات والمخزون والمعدات |
| `demo.employee` / `demo.engineer` / `demo.supervisor` | موظف | مهامه وحضوره وإجازاته وملفه فقط |

> جميع البيانات التجريبية مُعلَّمة (`is_demo`) وتظهر عليها شارة «تجريبي» مع شريط تنبيه أعلى النظام. تُحذف بالكامل من **الإعدادات ← البيانات التجريبية** (للمالك) أو بالأمر `npm run demo:clear`، دون المساس بأي بيانات حقيقية أو بحساب المالك أو بسجل العمليات.

## 3. النشر على خادم الشركة

### الخيار أ: Docker (الأسهل)
```bash
cp server/.env.example server/.env    # املأ القيم (JWT_SECRET، OWNER_*، SMTP_*)
echo "DB_PASSWORD=كلمة-مرور-قوية" > .env
docker compose up -d --build
```
يقوم الحاوي تلقائياً بتشغيل الترحيلات وإنشاء حساب المالك عند أول تشغيل.

### الخيار ب: خادم Linux مباشرة
1. ثبّت Node.js 22 وPostgreSQL 16، وأنشئ قاعدة بيانات ومستخدماً مخصصاً لها.
2. `npm run install:all && npm run build && npm run setup`
3. شغّل `npm start` عبر مدير عمليات (systemd أو pm2).
4. ضع خلفه Nginx مع شهادة HTTPS، واضبط `COOKIE_SECURE=true` و`TRUST_PROXY=1`.
5. جدولة النسخ الاحتياطي اليومي: `0 2 * * * cd /opt/tal-ems/server && npm run backup` (يحتاج `pg_dump`)، مع نسخ مجلد `storage/uploads`.

**قبل الإطلاق:** غيّر `JWT_SECRET`، احذف البيانات التجريبية، فعّل المصادقة الثنائية لحساب المالك، واضبط SMTP لإرسال روابط استعادة كلمة المرور (بدونه تُطبع الروابط في سجل الخادم).

## 4. الصلاحيات (RBAC)

- **54 صلاحية** موزعة على 16 قسماً، و7 مناصب افتراضية. المالك يملك كل الصلاحيات دائماً ولا يمكن تقييده أو حذفه، ويجب أن يبقى مالك واحد نشط على الأقل.
- لكل منصب **مستوى سلطة** (المالك 100، المدير التنفيذي 80…). لا يستطيع أي مستخدم منح منصب مساوٍ لمنصبه أو أعلى منه، ولا منح صلاحية لا يملكها. لذلك فالمالك وحده من يعيّن المدير التنفيذي أو يعزله.
- يستطيع المالك إنشاء مناصب جديدة وتحديد صلاحياتها من **الإعدادات ← المناصب والصلاحيات**.
- التحقق يتم في الخادم على ثلاثة مستويات:
  1. **القسم**: هل يحق للمستخدم الوصول لهذا القسم أصلاً؟
  2. **السجل**: مدير المشروع يرى مشاريعه فقط، والموظف يرى مهامه وحضوره فقط.
  3. **الحقل**: الرواتب ورقم الهوية وقيم العقود لا تُرسل أصلاً لمن لا يملك صلاحيتها.
- إخفاء العناصر في الواجهة للتجربة فقط. أي طلب مباشر للـ API بدون صلاحية يُرفض (403/404).

### سير الاعتمادات
| العملية | يرفعها | يعتمدها |
|---|---|---|
| مصروف مشروع | مدير المشروع (لمشاريعه فقط) | المدير المالي / التنفيذي / المالك |
| طلب شراء ← أمر شراء | مدير المشروع / المشتريات | صلاحية `purchasing.approve` |
| إكمال مهمة | الموظف (تتحول إلى «بانتظار المراجعة») | منشئ المهمة / مدير المشروع |
| إجازة | الموظف | الموارد البشرية |
| قرار تشغيلي / استراتيجي | من يدير الاجتماعات | المدير التنفيذي / **المالك فقط** |
| بدء مشروع (من الدراسة إلى التنفيذ) | — | صلاحية `projects.approve` |
| مسير الرواتب | المالية | الاعتماد المالي |

## 5. سجل العمليات
تُسجَّل كل عملية حساسة (إضافة، تعديل مع القيم قبل وبعد، حذف مع نسخة من السجل، اعتماد، تغيير صلاحيات، دخول وخروج، تصدير، نسخ احتياطي) مع المستخدم والمنصب والوقت وعنوان IP.
**الحماية في قاعدة البيانات نفسها:** Trigger في PostgreSQL يمنع UPDATE وDELETE وTRUNCATE على الجدول، حتى لو حاول أحد ذلك مباشرة من قاعدة البيانات. الاستثناء الوحيد هو أرشفة المالك للسجلات الأقدم من سنة، حيث تُحفظ أولاً في ملف أرشيف ثم تُسجَّل عملية الأرشفة نفسها.

## 6. هيكل المشروع
```
server/
  migrations/          مخطط قاعدة البيانات (40+ جدولاً)
  src/permissions.js   كتالوج الصلاحيات والمناصب الافتراضية
  src/resources.js     تعريف كل قسم: الحقول، الصلاحيات، نطاق الرؤية، الاعتمادات، الإشعارات
  src/routes/          API العام (CRUD) + المصادقة + لوحة التحكم + التقارير + الإعدادات
  scripts/             setup / demo-seed / demo-clear / backup
client/src/
  components/ResourceView.jsx   جدول + بحث + فرز + تصفية + نموذج + تفاصيل + اعتمادات (مشترك لكل الأقسام)
  pages/               صفحات الأقسام الستة عشر
```

### إضافة قسم جديد مستقبلاً
1. أنشئ ملف Migration للجدول (مع عمود `is_demo`).
2. عرّف المورد في `server/src/resources.js` (الحقول، الصلاحيات، `scope`، والإجراءات إن وجدت)، وأضف صلاحياته إلى `permissions.js`، ثم شغّل `npm run setup` لمزامنتها.
3. في الواجهة يكفي `<ResourceView resource="اسم_المورد" />`، فالجدول والنموذج والتفاصيل تُبنى تلقائياً من تعريف الخادم.

## 7. ملاحظات وحدود حالية
- **PDF**: يُنشأ عبر نافذة الطباعة في المتصفح بقالب يحمل الشعار (اختر «حفظ كـ PDF»)، لأن مكتبات PDF على الخادم لا تشكّل الحروف العربية بشكل صحيح. ملفات Excel تُنشأ على الخادم مباشرة.
- **البصمة والموقع الجغرافي**: يُحفظ الموقع عند تسجيل الحضور إذا سمح المتصفح بذلك. جدول الحضور يدعم المصدر `biometric`، لكن الربط بجهاز بصمة محدد يحتاج تكاملاً مع واجهة الجهاز.
- **الإشعارات** تتحدث تلقائياً كل 45 ثانية، وليست لحظية عبر WebSocket.
- **البريد**: استعادة كلمة المرور تحتاج إعداد SMTP.
